# nx-pn plugin workspace

Generated by `npx @flowot/nx-pn init <name>`. This workspace holds the nx-pn
base in `devDependencies` and one or more plugins under `plugins/`. Each plugin
ships a **UI page + API**: the browser half renders a page in the nx-pn web
shell, the host half runs in the Node host, and every network call goes through
the host's audited `ctx.auditClient`.

## Layout

```
package.json            # root scripts + devDeps (the embedded @flowot/nx-pn base)
tsconfig.json
scripts/dev.mjs         # standalone dev loop: own host + watch + hot-upload
scripts/shared-dev.mjs  # join (or create) the shared host on :4560
scripts/build.mjs       # per-plugin build → dist/<id>.zip
plugins/<id>/
  manifest.json         # id / version / title + halves { host, browser }
  host.ts               # cordis plugin — the Node half
  host.test.ts          # node:test smoke tests for the tool endpoints
  browser-sidebar.tsx    # React half — flat page in the shell sidebar (default)
  browser-fullscreen.tsx # React half — claims the viewport, own sub-routes
  package.json
  tsconfig.json
```

Only ONE of `browser-sidebar.tsx` / `browser-fullscreen.tsx` exists — the layout
is fixed at scaffold time (`--layout shell|fullscreen`; add a plugin later with
`npx @flowot/nx-pn init-plugin <id> --layout fullscreen`).

## Dev loop

```bash
npm run dev            # standalone: probes/spawns its own host on :4560, uploads
                       # every plugins/<id>/, then watches plugins/ — change →
                       # rebuild → re-upload (hot-replace). Ctrl-C to stop.
npm run shared-dev     # join (or create) one shared host — use this when several
                       # plugin dirs should share a single shell
npm run build          # build the plugin named in the script → dist/<id>.zip
node scripts/build.mjs <other-id>   # build a different plugin in a multi-plugin workspace
npm test               # node:test + tsx — runs plugins/<id>/host.test.ts
npm run typecheck      # tsc over the plugin's *.ts / *.tsx
npm install            # once, after the scaffold, pulls the embedded base
```

The dev scripts are self-contained (inline watcher) — no hmr package involved.

## Contract

### manifest.json

```jsonc
{
  "schemaVersion": 1,
  "id": "<kebab-case, ^[a-z0-9-]+$>",
  "version": "0.0.1",
  "title": "Human Title",
  "halves": {
    "host":    { "entry": "host.js" },     // compiled from host.ts
    "browser": { "entry": "browser.js" }   // compiled from browser-*.tsx
  }
}
```

Page routing (path / order / layout / routes) is declared in code via
`ctx.pages.register(...)` on the browser half, not in the manifest.

### Host half — `host.ts` (Node ESM, esbuild `external: ['cordis']`)

```ts
export default async (ctx, config) => {   // config.name = manifest.id
  ctx.logger.info(`[${config?.name}] active`)
  ctx.auditClient.get(url)                 // audited HTTP, attributed to this plugin
  ctx.on('<id>/my-action', (payload) => ({ ok: true, data: {} }))  // a tool endpoint
  const t = ctx.pluginStorage.table('settings')   // per-plugin durable KV
  await t.put('key', value); t.get('key')
}
;(plugin as any).inject = ['auditClient']   // optional: delay activation until ready
```

`ctx.on('<id>/<action>', handler)` registers a **tool endpoint**; the browser half
invokes it with `ctx.hostCall('<id>/<action>', payload)`. The handler's return
value is wrapped in `{ ok, data?, error? }`.

`ctx.pluginStorage.table(name)` is this plugin's own durable namespace (survives
stop / remove / re-install); tables carry `get` / `put` / `delete` / `keys`.

### Browser half — `browser-*.tsx` (React, shared vendor chunk)

```tsx
export default (ctx) => {
  const Page = () => {                       // define inside so it closes over ctx
    const [n, setN] = useState(0)
    return <button onClick={async () => {
      const r = await ctx.hostCall('<id>/my-action', { n })  // → { ok, data, error }
      const a = await ctx.auditClient.get('https://...')     // proxied to host over WS
    }}>{n}</button>
  }
  ctx.pages.register({ pluginId: '<id>', path: '/<id>', title: 'Title', Component: Page })
}
```

`ctx.pages.register({ pluginId, path, title, order?, layout?, routes?, Component })`:
- `layout: 'shell'` (default) → flat page inside the shell's `<main>`
- `layout: 'fullscreen'` → plugin claims the whole viewport; render your own
  `<Routes>` and carry your own top bar. `routes: [{ path, Component }]` declares
  sub-routes relative to the page prefix (`'/'` = bare prefix); `Component` is the
  `*` fallback.

**Required externals** — the build keeps `cordis`, `react`, `react/jsx-runtime`,
`react-dom`, `react-dom/client`, `react-router-dom` **external** so the shell's
import map supplies one shared React. `scripts/build.mjs` asserts this on the
compiled output; breaking it silently doubles React.

## Build → install → publish

```bash
npm run build                                       # → dist/<id>.zip (manifest + host.js + browser.js)
curl -F zip=@dist/<id>.zip http://localhost:4560/api/plugins   # hot-add to a running host (live)
npx @flowot/nx-pn add file:.                        # ledger install (npm path; takes effect on next host start)
npm publish                                         # consumers: npx @flowot/nx-pn add <pkg>
```

Re-installing the same `id` (zip upload or ledger) **upserts**: the old run is
disposed and the browser half is re-pushed to every connected shell — at most one
active run per `manifest.id` at any instant.

## Pitfalls

- Editing the **root** `package.json` scripts: `build`/`test`/`typecheck` target
  the plugin scaffolded first. For other plugins call `scripts/build.mjs <id>`.
- Don't collapse the browser half back to a single fixed filename — the build
  discovers it by the `browser*.tsx` glob, and a stale name means `npm run build`
  fails with ENOENT.
- Plugin attribution comes from the calling fiber, so `ctx.auditClient` calls land
  on `/audit` with `initiator = <manifest.id>`; a `ctx.on` tool endpoint invoked
  from the browser is attributed the same way.
